Quicklean Point-of-sale web application

Sale encoding, report generation, consumable inventory, and customer database for a laundromat

Problem

The laundromat relied primarily on paper trails and physical receipts for day-to-day operations. Record-keeping is done manually and sales needed to be encoded by hand into spreadsheets to produce meaningful reports.

Constraints

  • Operations must not be interrupted by internet connection loss
  • The UI must be intuitive and easy to use for staff with little to no computer use background
  • Reports generated must reflect the transactions occuring on the specified reporting dates
  • Hardware used must be appropriately modest and easily replaceable to cut down on downtime and maintenance costs
  • Tracking and tagging of physical bundles of laundry per customer

Approach

Building an on-premises server that allows printing of job orders attached to laundry bundles. Application runs locally, with a barcode scanner to easily encode consumables, and a terminal for enncoding and recording of transactions.

End-to-end system: customer information entry, sales records, wash/dry transaction data, payment processing with change calculation, staff shift tracking, and inventory handling.

Implementation

Began well before the usage of AI and is still evolving based on the business needs. LAMP server running on Docker for easy deployment and system updates.

Running system handling daily operations. Evidence of end-to-end practical software development from business understanding through deployment and ongoing maintenance.

Result

Users report less friction and errors when issuing job orders. Discrepancies and errors in manual cashier duties have dropped significantly and are easily traced.

Homeserver

Ongoing maintenance of experiments, useful services, and data/media repositories that run my life

Problem

I want a machine separate from my workstation that I can leave runninng 24/7 to serve useful applications for my day-to-day.

Constraints

  • Must be remotely accessible
  • Cheap to run
  • Maintainable, flexible, and extensible

Approach

Initial implementation involves an old laptop from my college days (around 2013). Installed a linux server distro and docker to mannage individual applications.

Have since upgraded to a modern (for 2025) machine and is running a headless linux server.

Implementation

  • Multiple directories with docker-compose files manage container configurations
  • Tailscale for full access with a cloudflared tunnel container to provide wider internet access
  • Domain configured with cloudflared tunnel to provide 'friendly' DNS resolution

Result

My data is owned by me - media, financial/budgets, smart home devices, and LLM experiments all run locally at home, and is accessible on my mobile devices.
